## READ THIS FIRST (the 6 things that will save you time)

1. **`ObjectiveHandler.java` is DEAD CODE.** `scoreStartingCard` / `setObjective` / the `OBJECTIVE_REQUIREMENTS` map are never called anywhere in `src/` (verified codebase-wide). If you "fix" an objective by editing that map, it is a silent no-op. The LIVE objective brain is `ObjectiveAnalyzer.java`.
2. **`ObjectiveAnalyzer.java` is the live, text-driven objective brain.** It regex-parses the objective's game text into location/required/pullable sets that the evaluators consult. Named per-objective special-cases live in `parseFlipCondition` (see the V25 ISB / Hunt Down / V160 Shield blocks, and now V186).
3. **The temp-id trap in `evaluateDeployLocation`.** Reserve-deck "deploy a location" picks arrive as `ArbitraryCardsSelectionDecision` with cardIds `temp0`/`temp1`. The candidate loop resolves cards via `findCardById(Integer.parseInt(cardId))`, which **throws** on temp ids before any scoring runs, so the +150 objective bonus (and V29.6/V23/etc.) never apply and every candidate ties at the +50 base. Resolve from `context.getBlueprints()` (index-parallel) instead. This affects ANY objective whose setup deploys a location from Reserve, not just mine.
4. **`context.getTestingTexts()` is never populated for Rando** (only `setCardIds` + `setBlueprints` are called in `buildEvaluatorContext`, RandoCalAi ~922-945). Match candidates by blueprint id, not title, in evaluator code.
5. **Blueprint id format has no leading zero:** `Card208_051` is `"208_51"`, not `"208_051"`.
6. **You cannot compile on the host** (mvn present, no JRE). Compile inside the running app container — see "Build + verify" below.

## Build + verify (the process we all share)

Host has `mvn` but **no JRE** — compile inside the running app container, which bind-mounts the repo at `/opt/gemp-swccg`:

```
docker exec gemp_swccg_app_1 bash -lc 'cd /opt/gemp-swccg/src && mvn -q -pl gemp-swccg-server -am compile 2>&1 | tail -20; echo "EXIT=${PIPESTATUS[0]}"'
```

`EXIT=0` with no error output = clean. Your host edits are visible in-container via the bind mount, so this compiles your working tree. Compiling does NOT deploy — the running jar stays old until a full rebuild + restart.

For AI-logic changes, do an adversarial verify before claiming done (do the magnitude boundary-math: does the new score actually win, and does it dominate without breaking neighbors). The temp-id trap is exactly the kind of thing that compiles fine and does nothing.
