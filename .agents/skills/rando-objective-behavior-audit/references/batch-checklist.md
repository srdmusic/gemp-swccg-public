# Objective Family Batch Checklist

## Preflight

- [ ] Read `AGENTS.md`, `resources/BUILD_AND_DEPLOY.md`, and the current takeover handoff.
- [ ] Check async mailbox and repo mailbox.
- [ ] Record clean base SHA and branch.
- [ ] Confirm the worktree is isolated from unrelated dirty work.
- [ ] Confirm no engine or card Java is writable for this task.
- [ ] Name one writer/integrator.

## Source law

- [ ] Read front objective card Java.
- [ ] Read back objective card Java.
- [ ] Read supporting route cards one level upstream.
- [ ] Record exact blueprint IDs and true twin printings.
- [ ] Record front trigger timing and full `allOf`/`anyOf` law.
- [ ] Record back trigger, flip-back, out-of-play, or hard-loss law.
- [ ] Record exact control, occupy, presence, count, persona, species, and typed-filter semantics.
- [ ] Record strict count comparisons and `SpotOverride` behavior.
- [ ] Separate native trigger, strategic driver, and payoff.

## State machine

- [ ] List every current missing requirement.
- [ ] List the next legal candidate for each missing requirement.
- [ ] Calculate required Force for deploy, move, battle, weapon, destiny, and maintenance.
- [ ] Identify sole enablers and expendable duplicates.
- [ ] Define front-side close condition.
- [ ] Define post-flip hold, payoff, release, flip-back, and terminal-hazard conditions.

## Existing ownership

- [ ] Search rulebook and live evaluator/policy source.
- [ ] Check enclosing branches for `if (false)` and retirement markers.
- [ ] Identify the exact current winning distraction.
- [ ] Identify Pass and the strongest applicable safety veto.
- [ ] Choose typed facts owner, shared policy owner, and mirrored adapter call site.
- [ ] Reuse or amend an existing semantic rule ID when it already owns the behavior.

## Tests before implementation

- [ ] Native engine contract flips from every valid route.
- [ ] Native engine contract rejects every near miss.
- [ ] Back-side contract covers stability and hazards.
- [ ] Facts/state test distinguishes satisfied and missing legs.
- [ ] Policy test covers positive, negative, release, and close boundaries.
- [ ] Candidate decision test includes Pass, distraction, and near miss.
- [ ] Cross-phase test preserves downstream Force and route pieces.
- [ ] Force-loss and battle-forfeit tests protect sole enablers.
- [ ] Unrelated objective and wrong-print tests reject cross-talk.
- [ ] Rando and Chosen One winner parity test exists.

## Implementation

- [ ] Change only AI logic, AI tests, approved objective data, audit evidence, and required AI docs.
- [ ] Keep analyzer/facts state-oriented.
- [ ] Keep scoring and vetoes in the live phase owner.
- [ ] Gate exact objective, side, state, legality, identity, affordability, and viability.
- [ ] Show boundary math against the actual competing score.
- [ ] Preserve existing tactical and legality vetoes.
- [ ] Mirror Rando and Chosen One adapters.
- [ ] Close the rule after its objective obligation is complete.

## Verification

- [ ] Focused family suite passes.
- [ ] Impacted shared-policy suite passes.
- [ ] Earlier objective compatibility suite passes.
- [ ] Normalized bot source parity passes.
- [ ] Clean full reactor passes or any unrelated failure is independently proven pre-existing.
- [ ] Clean async package passes.
- [ ] Changed class bytes match `target/classes`, server jar, and `web.jar`.
- [ ] Objective data bytes and hash match source and both jars.
- [ ] Diff contains no engine, card, client, database, or deck-library production change.

## Deployment

- [ ] Freeze new tables and confirm zero active games.
- [ ] Save the prior `web.jar` for recoverability.
- [ ] Restart or recreate the JVM after packaging.
- [ ] Verify host and container jar hashes.
- [ ] Verify JVM start is later than jar mtime.
- [ ] Verify HTTP 200 and clean startup.
- [ ] Restore AI tables, private games, stat tracking, and new-account switches.
- [ ] Run Rando versus Chosen One automated games.
- [ ] Tell Steve the objective family is ready for his live test.

## Seal

- [ ] Update both AI history files.
- [ ] Update audit record and proof gate.
- [ ] Regenerate the rulebook only if its extractor represents the new rule honestly.
- [ ] Commit one coherent objective-family batch.
- [ ] Publish the sealed feature branch only to Steve's fork when authorized.
- [ ] Never merge or push PlayersCommittee branches.
- [ ] Send K2/Codex mailbox evidence with commit, tests, hashes, replay IDs, and known limits.
