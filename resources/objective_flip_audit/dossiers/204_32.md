## CLASSIFICATION: SMALL_SHARED_EXTENSION (nested allOf-inside-anyOf)
The flip-back is FIT (single `occupy` leg, `"<",2`, class `battleground`). The FRONT is OR-of-ANDs: a flat `alternatives` list under one `mode` cannot express anyOf-of-(2-leg allOf). Each branch pairs DIFFERENT relations on DIFFERENT location classes (control system + occupy sites, vs the swap), so it cannot be flattened.
- **EXTENSION (shared with 109_4):** let a `FlipLocationAlternative` carry an optional nested `allOf` sub-group (one level): `alternative.subLegs : List<FlipLocationAlternative>` evaluated as an inner allOf. Then front = one preFlip rule, `mode:anyOf`, two alternatives each a subLegs pair. Precedent-shaped: mirrors how `opponentConstraint` already nests a sub-condition on an alternative.
- Recipe once extension lands:
  - `flipLocationRules[0]` preFlip/flip, anyOf: `[{subLegs:[control Jakku_system, occupy Jakku_battleground_site count>=2]}, {subLegs:[occupy Jakku_system, control Jakku_battleground_site count>=2]}]` (all includeExcludedFromBattle:true).
  - `flipLocationRules[1]` postFlip/flipBack, allOf, alt `{relation:occupy, controller:self, locationFilterKey:battleground, count:{"<",2}, includeExcludedFromBattle:true}`.
