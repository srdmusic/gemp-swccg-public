## T4.1 Move Clobber Ladder

### Design
RANK-AS-BAND-OFFSET inside MoveEvaluator only; CombinedEvaluator's additive merge (EvaluatedAction.mergeFrom, additive) is untouched. Each move action accumulates today's fine-scores via addReasoning exactly as now, but the per-action loop gains two tracked fields: `rank` (int, max of all matched rank-predicates, default R1) and `vetoed` (boolean). A finalizer just before `actions.add(action)` (ME:1707-1711) applies: veto → addReasoning(-100000); else addReasoning(rank base: R4=+20000 mandatory transit, R3=+12000 survival, R2=+6000 doctrine, R1=0), with the accumulated non-base fines clamped to ±2800 (log "LADDER CLAMP" if hit). All early `return`s in rankMoveFromLocation (ME:1767, 1772, 1780, 1788, 1845, 1858) are removed so every block always runs; former hard-returns become R1-internal weights: V37.1 CRUSH/FAVORABLE -9999→-1500 (no return), V85 -2000→-800 (no return). setScore ordering hacks (V53b ME:1683, V60 ME:1692) are commented out and replaced by R4 claim / veto flag. Rank claims: R4 = V53b Safehouse→Corridor + Mapuzo-exit, plus (cross-file) ATE's V60 game-text transit raised +9999→+20000 so both transit arms share the band; R3 = threat==RETREAT tier, V59 DOOMED escape, V91 landed-ship take-off/disembark; R2 = V35/V29.12 hunt, V29.13 toward-group and positive drain-delta, V34/V36/V111 contest+advance, V29.7 weapon-hunter and ATTACK/SPREAD (both newly gated on isAdjacentSites reachability to prevent the destination-blind Rey class), V73 shuttle, V22.2/V22.5/V31 consolidation, V53 spy-follow/reposition; VETO(-100000) = V160 cancel-loop hard branch, V38.3 wrong-direction + Castle (with a new R4 carve-out mirroring the V111 precedent, so mandatory transit can exit to an empty site), V135 self-move-alone (was -2000, strengthened), V49/V67f landing guard, V47 as gated today, and V137's winnability arm now failing the shared canWinAt. The default "No strategic reason to move" -50 (ME:2447) moves into the finalizer, applied only when rank==R1 and no positive doctrine fine matched.

Cross-evaluator bound VERIFIED: for actions MoveEvaluator scores (keywords ME:52-55), ATE's movement-region non-veto contributions are V35.4 +250/+150 (as fixed today, mover-scoped, never undercover mover), V29.7 Vader-Castle -300, V67ae -300 ("Move from…to here" matches ME keyword "Move from"), V169 soft-block -250 (budget 3) — single-rule max +250/-300, worst stack -550, i.e. inside the claimed ~±400 per rule and far inside the 6000 band gap. ATE's ±9999-class arms either never co-sum with ME (V60 transit text matches no ME keyword; V103 ≤+300 is MULTIPLE_CHOICE which ME.canEvaluate rejects) or are veto-class and get aligned: V134 -9999→-100000 (its "Transport" text DOES co-sum with ME); V87 -3000 left as-is (fires only on R1 capacity-slot swaps, still kills vs Pass). Pass baseline verified 5.0 + situational bonuses ≤~45 (PassEvaluator.java:95), so any R2+ candidate beats Pass by construction while R1 candidates behave exactly as today. Band integrity: worst R2 intra-rank negative stack ≈ -2800 (clamped) - 550 (ATE) = R2 floor +2650 > worst R1 ceiling ≈ +1670 fines (V79 +1500 max) + 250 ATE = +1920. The shared predicates live in a NEW package `com.gempukku.swccgo.ai.models.rando.common` (no common/ exists yet under rando/), class `RandoMovePredicates`: `boolean canWinAt(SwccgGame game, GameState gs, String playerId, PhysicalCard site, float ourProjectedPower, float ourProjectedAbility, float ourForfeitTotal)` — true if clean win (power ≥ oppPower && ability ≥ 4, CDSE:253-254 parity) OR V181 tolerance (0 < gap ≤ 3 && oppDrainAt(site) ≥ 2 && ability ≥ 4 && (theirForfeit ≤ 0 || ourForfeit ≤ theirForfeit*1.25), ported from CharacterDeploySiteEvaluator:366-391) — plus `float drainAt(game, gs, loc, playerId)` and `float drainDelta(game, gs, from, to, playerId)` on engine getForceDrainAmount, which V85/V29.13 (already engine-based) and V67g/V67e/V67ae (icon-based today) all route through, resolving move-6's two-metric split.
